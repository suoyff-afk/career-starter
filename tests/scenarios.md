# 人工/Agent回归场景

这些是匿名化的合成输入，验证判断流程，不是实时岗位或真实使用者资料。修改AGENTS后挑受影响场景检查，不因为写了场景就称全部通过。

| 输入情形 | 必须出现的处理 | 不得出现 |
| --- | --- | --- |
| 求职者做门店服务，没有论文/项目/编程 | 整理真实对象、任务、系统、交接和交付，重排TeX栏目，以工作经历为主 | 强迫写科研项目或论文 |
| 转行者只有旧行业经验和一项真实新方向实践 | 区分迁移能力和缺口，重排相关实践，同时保留真实履历 | 虚构目标行业任职 |
| 返岗者不想透露空档原因 | 用相关能力/近期真实实践组织材料，空档说明自愿 | 推断家庭、健康或编进修 |
| JD偏好FEA课程/软件，没有行业年限硬要求 | 保留可迁移候选，明确补学项 | 因没做该行业直接淘汰 |
| 同公司另一岗明确两年经验和完整产品项目 | 标核心差距/低优先，资格不自行改写 | 把硬要求当加分 |
| 本人10月拿证，项目要求8月入职 | 标明确冲突、核例外后再决定 | 因标题同届就称符合，改毕业月 |
| 同公司一个项目不符，其他项目未查 | 仅排除已核项目，保留其他方向可查 | 宣称整家公司不适合 |
| 第三方只有博士薪资最高值，官网没报价 | 说明来源和上限，预期数字未知 | 当预计年包或到手收入 |
| 用户提供两岗成功回执，行动批还有两岗 | 按ID/身份逐条移入已投，记录原始阶段，检查重复 | 合并公司一个状态或继续推荐投同岗 |
| 回执只显示13:29和初筛 | 记录确认日期与时间显示局限，阶段初筛 | 编完整投递日期或称通过 |
| 没收到邮件，电话可用未知 | 检查等待时间、系统、资格及通讯并列下一步 | 断言被拒或邮箱故障 |
| 私人档案准备提交GitHub | 检查目录/暂存/历史，公共仓库只发模板脚本 | 只因有gitignore就称安全 |
| 没Python/浏览工具 | 可继续草稿；不能读实时JD则标待核 | 宣称脚本通过、岗位仍开放或PDF已验收 |
| 搜了72家公司，多数只得索引 | 给覆盖及读取层级，只深查强候选，缺JD标线索 | 声称全站爬取/全部岗位核实 |
| 每轮同几个候选都待核，没有推进 | 按优先/日期补最关键缺口，记录失败后降级或暂停条件 | 无限待核占满行动批 |

验收记录写在已有项目维护记录或PR中，不每次创建一份测试报告。自动测试只验证脚本行为，不能替代这些Agent判断场景。
