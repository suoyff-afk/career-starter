# 面试口述、练习与复盘

帮助用户讲清真实经历，并检验理解。不是代写一套需要死背的标准答案。

## 开始前
- 按任务读取已有岗位信息、相关经历和面试记录；事实以原件、项目证据与本人确认为准。不要重复访谈已知信息。
- 区分“整理稿件”“模拟练习”“面试复盘”。用户只要稿件就交稿，不强迫进入练习。
- 按实际面试阶段与时长确定重点；技术面与终面材料分开。未明确的面试官身份或流程不能说成确定。
- 保留用户认可的研究/工作主线、顺序和重点；不把科研术语、固定时长或某公司的问题强加给所有人。

## 一题一练
1. 每次只问一道题，等待用户回答；已有回答就从该回答开始，不重问开场题。
2. 先判断卡在事实、概念还是表达。纠正最影响理解的一两点，避免整段推倒重写。
3. 表达问题：保留原意，整理为自然短句。先回答问题，再给相关经历与结果；不强行每题套同一结构，不用空泛口号或绕口结语。
4. 概念问题：用本人项目或一个小例子解释，再让用户换自己的话回答；不要只换一段更流利的台词掩盖理解缺口。
5. 按用户给定长度；没有要求时一般答案约30—60秒，自我介绍按场景调整。需要稿件时只给“问题—回答—关键词”；技术细节集中末尾小表，不穿插长讲义。
6. 用户未表示继续，尤其明确说“先别下一题”时，留在本题。准备好后可问一个相关追问；不连续抛出问题清单。
7. 用户可选择跳过；跳过或读过答案不记作掌握。区分已讲解、能独立复述、能应对迁移追问，不凭助手生成内容升级状态。

## 证据与复盘
- 记不清的模型、参数、验证或结果先查已有PPT、代码/配置和记录。只查本题所需，不展开完整代码审计。
- 不能为“更有说服力”编造用过的模型、贡献或成绩。用已证实的选择依据组织有力度的回答；拟尝试的方法不能写成实际经历。
- 技术术语可简化，关键区别不能混淆；缺证据放核对项，口述回答不堆免责话术。
- 将面试回忆、核实事实、建议答法分开。同一主问题的连续追问合并为一个有结构的条目；不同主题不要挤成一题。
- 只有要求保存/更新时写入现有面试稿或能力记录，不每次练习新增文件。只记实际问题、关键修正和一个待补点；不要复制整段聊天。
- 发现持续知识缺口时记入现有能力记录；需要长期学习计划才转personal-learning-planner，不在本Skill再建立一套课程。

验收：回答切题、口述顺畅、贡献有依据；理解是否掌握以用户实际作答为准。训练表现不等于实际面试通过。
