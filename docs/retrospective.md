# 复盘：把遇到的问题变成系统规则

以下来自早期求职协作中的问题，已匿名化并概括为通用情形。目的是让新使用者避免重犯；不是录取效果统计，也没有包含原使用者的私人数据。

| 遇到的问题 | 根因 | 本项目的改进 | 验收方式 |
| --- | --- | --- | --- |
| 已投岗位又出现在行动批 | 靠聊天记忆、近似名称合并、状态多处记录 | tracker唯一入口，按实体/批次/ID去重，回执后逐岗同步 | 同岗不同时占已投与待投；scenarios回执场景 |
| 名称像仿真就推，或像结构就排除 | 没读完整JD；把能力差距误当资格硬门槛 | 强候选完整JD，必需/加分/未知分开；根据迁移证据判断 | 宽条件岗保留，明确经验岗标差距 |
| 实习或方向登记被当正式具体岗 | 只看标题/批次，没有核正文与用工类型 | 核全职/实习、具体职责、岗位ID；登记入口只标线索 | 推荐中用工类型和证据层级清楚 |
| 同届名称掩盖毕业月份不符 | 没核拿证与固定入职；误把学历下限当偏好 | 日期分别记录，时间差保留如实申请／协商路径；不实承诺字段不提交；学历和实际职责一起看 | 不编日期，不泛化到公司其他项目 |
| 推荐公司范围窄或搜索层级说不清 | 只搜熟悉名词，检索时间被当覆盖质量 | 从任务/迁移能力扩展行业，记录公司与渠道及读取层级 | 说明实际范围、未读部分和筛选理由 |
| 薪资很笼统或数字口径混杂 | 邻岗、历史值、宣传上限拼为个人预期 | 单列来源/日期、币种/税前后/薪数、本岗与参考 | 不从最高值承诺报价，未知允许保留 |
| 简历/自我评价空泛 | 用通用形容词替代本人任务和贡献 | 真实对象、行动、方法和结果；没有数字也可写清楚 | 使用者能解释每句话，不编“学习强”等证据 |
| 为填满档案反复追问，已确认信息又问一遍 | 把模板当必答问卷，未先查原件，也未区分缺口是否影响行动 | 现有资料能回答就附来源补齐；只问影响下一步且无法自行核实的问题，其他保留未知 | 已确认项不重复问；无关缺失不阻塞准备；关键冲突不猜填 |
| 档案很长却难以复制 | 事实、流程、状态和长分析混在一处 | 档案放事实，规则放方法，总表放状态；短网申文本按需生成 | 信息只有一个权威位置，必要内容可直接复用 |
| 按科研者经历固定所有简历 | 用上一使用者身份代替新使用者访谈 | 一份可编辑TeX模板，栏目按经历重排/删减，不强制论文或技术内容 | 中文客服、英文学生合成样例及判断场景检查 |
| 无回复就认为简历失败 | 缺等待时长、企业状态与通讯证据 | 分别核节奏、资格、针对性和联络，选择最有证据的一项改 | 无确定证据不下拒绝/通讯故障结论 |
| 待核岗位一直停在行动批 | 不确定项无责任/日期，过期任务未处理 | 记录最小下一步及期限；二次复查仍无JD时写降级/重启条件 | 行动批无无限期待核；到期可执行 |
| 简历和文档版本越来越多 | 每轮另建文件，默认逐公司简历 | 一个事实主稿，少量方向版；状态维护原表 | 无重复主表/无用途空目录，提交版本可追溯 |
| 定时任务没有运行或通知无变化 | 只写安排，未验证调度及运行状态 | 明确创建/故障；无实质变化静默 | 仅实际创建才称启用，失败报告 |
| 编写了检查就声称成功 | 把草稿、编译、PDF、事实和ATS混为一谈 | 分阶段状态和验收，自动/人工场景分开 | 有对应证据才称通过，不保证ATS/录取率 |
| 用新HTML方案代替实际LaTeX却称复现 | 没读取真实源模板，把设计当成既有经验 | 已移除JSON/HTML原型，读取原TeX后提取排版，采用本地编译 | 区分原版机制、新适配、实际测试及未验证范围 |
| 命令工具启动失败被误称TeX不能用 | 未区分沙箱启动与编译器报错 | 先读工具日志，再对实际编译器做最小检查 | 原模板可编译不等于新模板或整个系统通过 |

## 本次整理得到的维护规则

- 公司目录过多：仅真实沟通／面试进度单列，其余并入一张比较表；状态只记tracker。
- 用归档链接代替整理：有用内容直接放到对应文件，核对独有事实及依赖后清理重复旧稿，不建立归档堆积。
- 表格后再写重复补充：招聘链接放岗位名，必要限制和来源并入表格；只显示一个综合暂评分，资料不足保留未知。
- 精简时丢了事实或源码：已投证据、资格来源、PDF与对应TeX必须保留；检查链接和岗位身份后才宣布完成。
- 把目录误写成Markdown：原件目录按实际路径引用，不生成虚构的materials.md或空文件。

## 一轮工作的有效性检查

本轮应该让使用者更接近一个实际目标：档案清楚、简历可投、岗位资格明确、申请完成、面试准备充分或一个缺口得到验证。只有更多记录却没有可执行动作，不算充分推进。

每项待核只写最关键的缺口和一个带日期动作。过期动作先处理，不把旧日期当下次计划。查不到资料就标局限，并按本人优先级决定降级或换目标；不是让所有候选一直停在未知。

使用者可以以有限数据观察：准备耗时、可投材料是否完成、重复记录数、有完整JD的行动岗位比例、带日期的待办比例、实际投递/回复/面试与等待时长。录取结果受个人、企业和市场影响，这些不能直接证明系统因果效果。

## 验证边界

本地脚本测试、合成简历编译/目检、规则场景和官方网页查阅分别检查，最终状态见README。合成例子不是真实人的背景，不代表录取效果；本机成功也不证明所有系统或字体可用。README已记录2026-10-08从真实GitHub链接匿名读取、全新克隆和脚本检查通过；本轮仅核对文档一致性，未重跑该历史验收，也未补造当时提交标识。仍需让新使用者按自身真实材料试用，记录卡点。没有完成的验证不称成功。
